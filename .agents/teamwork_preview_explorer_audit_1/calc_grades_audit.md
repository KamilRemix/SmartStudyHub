## 1. Executive Summary (Краткое резюме)

Проведен детальный построчный аудит математической логики, формул, обработки дробей, коэффициентов/весов, академических периодов (четверти/семестры), симуляций «Что если?», стратегического планирования оценок и сохранения истории/состояний.

### Ключевые выводы:
1. **Калькулятор**:
   - **В мобильной версии уже реализована мощная математическая база**: полноценный алгоритм Дейкстры (Shunting-Yard) с переводом в обратную польскую нотацию (RPN) в `expressionParser.ts`, поддержка скобок, неявного умножения (`5(2+3)`), унарного минуса, форматирования точности в 12 значащих цифр (полный аналог `parseFloat(val.toPrecision(12))` из веба), а также лента истории на базе `AsyncStorage` (в старом вебе истории калькулятора не было вовсе!).
   - **Калькулятор дробей** в мобильной версии превосходит старый веб: рассчитываются НОД, НОК, перевод в неправильные дроби, 4 базовые операции, сокращение, смешанный вид и 5-шаговое нативное визуальное решение.
   - **Обнаруженные нюансы калькулятора**:
     - В `StandardCalculatorView.tsx` проверка последовательных операторов заменяет предыдущий оператор на новый (`isOp && isPrevOp`), что блокирует ввод унарного минуса после умножения/деления (например, `5 × -3`).
     - Семантика процента `%`: в Shunting-Yard реализована как деление на 100 (`x / 100`). В сложных цепочках вида `100 + 10%` результат равен `100.1`, тогда как бытовые калькуляторы ожидают `110`.
2. **Средний балл (Grades / GPA)**:
   - **Суперчардж в мобильной версии**: в старом веб-проекте расчет был плоским средним арифметическим без весовых коэффициентов и без разбивки на четверти/семестры. В `mobile-expo` уже заложены коэффициенты (1.0x Ответ, 1.5x Тест, 2.0x Контрольная, 3.0x Экзамен), выбор четвертей (1-4)/семестров (1-2) и сводная годовая таблица (`AnnualTableCard`).
   - **Критические пробелы (Gaps) в мобильной версии по отношению к требованиям и старому вебу**:
     - **Отсутствие режима «Быстрый подсчет» (`__QUICK_CALC__`)**: в старом веб-проекте первой вкладкой шел локальный временный расчет без привязки к названию предмета, не сохраняемый в облако. В мобильном приложении пользователь вынужден обязательно выбирать или создавать предмет.
     - **Статичность модального окна порогов (`ThresholdsModal.tsx`)**: окно позволяет менять шкалу (5-балльная / US) и режим периодов, но отображает пороги в виде статического текста без полей ввода `TextInput`, тогда как в вебе пользователь мог кастомизировать пороги (например, 4.60 для отличника в гимназиях).
     - **Отсутствие интеграции с Firebase**: модуль `grades` в `mobile-expo` сохраняет данные исключительно в локальный `AsyncStorage` (`@smartstudy_grades_data`). Синхронизация с Firestore/Realtime Database проекта `studio-9933447149-80d6a` отсутствует.
     - **Несовместимость схемы данных**: легаси веб хранит в Firebase плоский объект `{ "Алгебра": [5, 4, 5] }`, а мобильная версия — массив объектов предметов с уникальными ID, весами и периодами: `[ { id, name, targetGrade, grades: [ { id, value, weight, period, date } ] } ]`. Необходим адаптер обратной совместимости при интеграции Firebase.
3. **Сохранение верстки (UI Preservation R5)**:
   - Вся текущая нативная верстка (`StyleSheet`, компоненты карточек, таб-бары, чипы) сверстана профессионально и полностью соответствует дизайн-системе. Доработка бизнес-логики и Firebase **не требует изменения стилей и JSX-структуры**, а лишь внедрения состояний, адаптеров и сервисных методов.

## 3. Детальный аудит математики и алгоритмов

### 3.1. Стандартный калькулятор

#### Реализация в легаси веб (`public/renderer.js`, строки 1111–1115):
```javascript
evaluate() {
    let e = this.display.value;
    if (!e) return void(this.resultDisplay.textContent = "");
    e = e.replace(/×/g, "*").replace(/÷/g, "/");
    try {
        const t = new Function("return " + e)();
        "number" == typeof t && Number.isFinite(t) 
            ? this.resultDisplay.textContent = parseFloat(t.toPrecision(12)) 
            : this.resultDisplay.textContent = "";
    } catch(e) {
        this.resultDisplay.textContent = "";
    }
}
```

#### Реализация в мобильном приложении (`expressionParser.ts`):
- Алгоритм **Shunting-Yard** с построением очереди токенов RPN и последующим вычислением стека.
- Таблица приоритетов:
  - Сложение `+`, вычитание `-`: приоритет 1 (левоассоциативные)
  - Умножение `*`, деление `/`: приоритет 2 (левоассоциативные)
  - Процент `%`: приоритет 3
  - Унарный минус `~`: приоритет 4 (правоассоциативный)
- Точность:
  ```typescript
  export function formatPrecision(val: number): string {
    if (!Number.isFinite(val) || Number.isNaN(val)) return 'Error';
    const precise = parseFloat(val.toPrecision(12));
    if (Math.abs(precise) >= 1e12 || (Math.abs(precise) > 0 && Math.abs(precise) < 1e-6)) {
      return precise.toExponential(6).replace('e+', 'e');
    }
    return precise.toString();
  }
  ```
- **Замечание по операторам**:
  В `StandardCalculatorView.tsx` (строка 37):
  ```typescript
  if (isOp && isPrevOp) {
    return prev.slice(0, -1) + char;
  }
  ```
  Если пользователь вводит `5 × - 2`, знак `×` заменяется на `-`. Рекомендуется разрешить ввод знака `-` после `×` или `÷`, чтобы поддерживать унарный минус для отрицательных множителей.

### 3.2. Калькулятор дробей

#### Математические формулы (полная эквивалентность между веб и мобильной версией):
1. **Перевод смешанного числа в неправильную дробь**:
   $$\text{num} = \text{sign} \times (|\text{whole}| \times \text{den} + \text{numPart})$$
2. **Наибольший общий делитель (НОД / GCD)**:
   Алгоритм Евклида: $\text{gcd}(a, b) = \text{gcd}(b, a \pmod b)$
3. **Наименьшее общее кратное (НОК / LCM)**:
   $$\text{lcm}(a, b) = \frac{|a \times b|}{\text{gcd}(a, b)}$$
4. **Сложение и вычитание**:
   $$D = \text{lcm}(d_1, d_2), \quad m_1 = \frac{D}{d_1}, \quad m_2 = \frac{D}{d_2}$$
   $$\text{resNum} = (\text{num}_1 \times m_1) \pm (\text{num}_2 \times m_2), \quad \text{resDen} = D$$
5. **Умножение**:
   $$\text{resNum} = \text{num}_1 \times \text{num}_2, \quad \text{resDen} = d_1 \times d_2$$
6. **Деление**:
   $$\text{resNum} = \text{num}_1 \times d_2, \quad \text{resDen} = d_1 \times \text{num}_2$$
7. **Сокращение**:
   $$g = \text{gcd}(|\text{resNum}|, |\text{resDen}|), \quad \text{reducedNum} = \frac{\text{resNum}}{g}, \quad \text{reducedDen} = \frac{\text{resDen}}{g}$$
8. **Выделение целой части**:
   $$\text{whole} = \text{trunc}\left(\frac{\text{reducedNum}}{\text{reducedDen}}\right), \quad \text{rem} = |\text{reducedNum} \pmod{\text{reducedDen}}|$$

В мобильном приложении шаги выводятся через компонент `FractionStepRenderer.tsx`, формируя полноценный визуальный ход решения.

### 3.3. Модуль среднего балла (Grade Average)

#### 1. Взвешенное среднее (Weighted Average):
$$\bar{x} = \frac{\sum_{i=1}^n (v_i \cdot w_i)}{\sum_{i=1}^n w_i}$$
где $v_i$ — значение оценки (1–5 или 0.0–4.0 GPA), $w_i$ — вес оценки (1.0, 1.5, 2.0, 3.0).

#### 2. Расчет годовой оценки (`calculateAnnualAverage`):
$$\text{AnnualAvg} = \frac{\sum_{p \in P_{\text{active}}} \bar{x}_p}{|P_{\text{active}}|}$$
где $P_{\text{active}}$ — периоды (четверти или семестры), в которых есть хотя бы одна оценка.

#### 3. Расчет общего среднего балла ученика (`calculateGlobalAverage`):
$$\text{GlobalAvg} = \frac{\sum_{s \in S_{\text{active}}} \text{Avg}_s}{|S_{\text{active}}|}$$

#### 4. Симулятор «Что если?» (`simulateWhatIf`):
$$\bar{x}_{\text{sim}} = \frac{\sum_{\text{current}} + (v_{\text{hypo}} \cdot w_{\text{hypo}})}{W_{\text{current}} + w_{\text{hypo}}}, \quad \Delta = \bar{x}_{\text{sim}} - \bar{x}_{\text{current}}$$

#### 5. Стратегический решатель (Strategy Engine):
- **Основная стратегия (вычисление необходимых отличных оценок $k$)**:
  Требуется достичь порогового балла $T$ (например, $4.50$):
  $$\frac{S + k \cdot G_{\max}}{W + k} \ge T \implies k \cdot (G_{\max} - T) \ge T \cdot W - S$$
  $$k = \max\left(1, \left\lceil \frac{T \cdot W - S}{G_{\max} - T} \right\rceil\right)$$
  где $S = \sum (v_i \cdot w_i)$, $W = \sum w_i$, $G_{\max} = 5$ (или $4.0$ GPA).
- **Смешанный вариант (Mixed)**:
  Имитация чередования высшей оценки (5) и хорошей оценки (4) до 20 итераций:
  $$S \leftarrow S + 5 \text{ (шаг 1)}, \quad S \leftarrow S + 4 \text{ (шаг 2)}, \dots$$
- **Исправление оценки (Remediation)**:
  Поиск минимальной оценки $v_{\min}$ с весом $w_{\min}$ и замена на высшую оценку $G_{\max}$:
  $$S_{\text{fix}} = S - v_{\min} \cdot w_{\min} + G_{\max} \cdot w_{\min}$$
  $$\bar{x}_{\text{fix}} = \frac{S_{\text{fix}}}{W}$$
  Если $\bar{x}_{\text{fix}} \ge T$, пользователю выводится рекомендация о пересдаче.

### 4.3. Требования к адаптеру синхронизации с Firebase (R4 + R2):
Если мобильное приложение авторизуется под существующим аккаунтом из веб-версии, данные в Firebase будут иметь вид словаря `Record<string, number[]>`.
При загрузке из Firebase в мобильное приложение необходим конвертер:
```typescript
function migrateWebGradesToMobile(webData: any): SubjectItem[] {
  if (Array.isArray(webData.subjects)) return webData.subjects;
  if (typeof webData.subjects === 'object' && webData.subjects !== null) {
    return Object.entries(webData.subjects).map(([name, grades]) => ({
      id: `subj_${encodeURIComponent(name)}`,
      name,
      targetGrade: webData.settings?.gradingSystem === 'us-letter' ? 'A' : 5,
      grades: (Array.isArray(grades) ? grades : []).map((val, idx) => ({
        id: `g_${Date.now()}_${idx}`,
        value: typeof val === 'number' ? val : 5,
        weight: 1.0,
        period: 'q1',
        date: Date.now(),
      })),
    }));
  }
  return [];
}
```

## 5. Обнаруженные различия и пробелы (Gaps)

### GAP 1: Отсутствие режима «Быстрый подсчет» (`__QUICK_CALC__`)
- **В вебе**: Пользователь видит в полосе чипов предметов кнопку «Быстрый подсчет» со значком молнии. При клике можно сразу нажимать цифры оценок и получать средний балл без ввода названия предмета. Данные хранятся в `quickCalcGrades` и не засоряют базу.
- **В мобильной версии**: Чипы показывают только созданные предметы. Если предметов нет, экран пуст.
- **Решение**: Добавить первым фиксированным чипом в горизонтальный список предметов чип «Быстрый расчет» (`id: '__QUICK_CALC__'`) без изменения существующей стилизации (`styles.subjectChip`).

### GAP 2: Редактирование числовых порогов в `ThresholdsModal.tsx`
- **В вебе**: Вкладка порогов содержала поля ввода для изменения значений (например, изменить порог пятерки с 4.50 на 4.65).
- **В мобильной версии**: `ThresholdsModal.tsx` содержит переключатели шкалы и периодов, а блок порогов сделан в виде статического текста.
- **Решение**: Добавить числовые поля `TextInput` в блок порогов с сохранением в `settings.thresholds`.

### GAP 3: Интеграция с Firebase JS SDK (`studio-9933447149-80d6a`)
- **В вебе**: При авторизации пользователя через Google/VK/Email данные оценок мгновенно синхронизируются с `users/${uid}` в Firestore и Realtime DB.
- **В мобильной версии**: Модуль оценок изолирован в `AsyncStorage`.
- **Решение**: Подключить модули `firebase/app`, `firebase/auth`, `firebase/firestore` в `mobile-expo` с сохранением fallback на `AsyncStorage` в оффлайн-режиме.
